# ЛР 6 · Воспроизводимая подготовка данных без утечки

**Вход:** GroupLens MovieLens Latest Small (`ml-latest-small.zip` или каталог CSV). **Код:** [prepare_dataset.py](prepare_dataset.py) · **Тесты:** [test_prepare.py](test_prepare.py) · **Версия:** `cinematch-labels-v1.0.0`.

## Запуск

```bash
python prepare_dataset.py --source /path/to/ml-latest-small.zip --output prepared
# Или (при наличии доступа к Интернету):
python prepare_dataset.py --output prepared
python -m unittest -v test_prepare
```

Скрипт использует стандартную библиотеку Python 3.11+ и **не публикует исходные данные**. При онлайн-запуске сначала пробует официальный ZIP GroupLens; при недоступности — проверенное GitHub-зеркало. Для каждого из четырёх CSV сверяет **точный Git blob SHA-1** с зафиксированным. При смене версии остановится и потребует сознательного пересмотра Data Card.

## Порядок обработки

1. Проверить разрешённый источник, схему, типы, ссылки на каталог, интервал 0.5–5 и шаг 0.5. Некорректное — в `exclusions.csv` с причиной, без молчаливого исправления.
2. Для одинаковых `(userId,movieId)` оставить запись с максимальным `timestamp` (при равенстве — более позднюю строку); исходный рейтинг не модифицировать.
3. Зафиксировать числовую метку по [инструкции v1](annotation_guideline.md), не считать отсутствие рейтинга негативом.
4. Разбить **у каждого пользователя** отсортированные уникальные временные группы на примерно 60/20/20. Взаимодействия с одинаковым `(userId,timestamp)` остаются целиком в одной части. Если уникальных timestamp меньше 3 — `not_evaluable` и исключить из офлайн-оценки.
5. `train_idf.json` вычислять по **уникальным фильмам, встретившимся в train**, используя только их жанры (формула сглаженного IDF `ln((1+N)/(1+df))+1`). Теги, оценки или названия test для fit не используются. Проверка: изменение жанров фильма, присутствующего только в test, не должно изменить train-IDF.
6. Проверить попарное отсутствие пересечений `(userId,movieId)` и `(userId,timestamp)` между train/validation/test и строгий порядок времени.
7. Сохранить фиксированные CSV, версию, входные SHA-256, выходные SHA-256 и manifest. Повторный запуск не должен менять результат при одинаковом источнике и параметрах.

**Создаваемые локально артефакты:** `prepared/clean_interactions.csv`, `train.csv`, `validation.csv`, `test.csv`, `not_evaluable.csv`, `exclusions.csv`, `pilot_labels.csv`, `train_idf.json`, `manifest.json`.

**Публично размещённые артефакты:** [сводный manifest](data_manifest_v1.json), [пилотный CSV](pilot_labels_v1.csv), документация, код и тесты. Приватизированный CSV с псевдонимными ID в GitHub не публикуется.

## Необходимые ограничения

- Отсутствие оценки фильма пользователем — **не негативная метка**; рекомендации оценивают на наблюдаемом holdout, указав ограниченную полноту разметки.
- В MovieLens нет времени добавления каждого фильма в каталог; поэтому историческая доступность кандидатов не доказана.
- Алгоритм хронологического разделения у существующих пользователей не измеряет cold start для совершенно новых пользователей.
- Метки user rating не являются экспертной оценкой жанра/творческого качества и не подтверждают реальные CTR или удовлетворённость.
- Генерация `train_idf.json` использует **train** и не «учится» на validation/test. После изменения схемы или порогов нужно поднять версию и заново оценивать модели.

## Обработка ошибок источника (исправление 08.11.2026)

При автоматической загрузке сначала проверяется GitHub-зеркало, к SHA которого привязана версия набора, затем официальный ZIP. Каждый источник проходит контроль файлов. При недоступности обоих показываются URL и непосредственные сообщения об ошибках; в Colab предусмотрена загрузка ZIP с локального компьютера. Нельзя автоматически принимать другой набор или отключать контроль суммы. Для самостоятельной диагностики: `python prepare_dataset.py --output prepared` или `python prepare_dataset.py --source ml-latest-small.zip --output prepared`.
