# Инструкция разметчика v1.0 — CineMatch

**Дата:** 08.11.2026 · **Группа:** МИК21 · **Объект:** одна оценка фильма пользователем MovieLens (`userId`, `movieId`, `rating`, `timestamp`).

## Назначение

Преобразовать уже существующую экспертную/пользовательскую шкалу оценки MovieLens (0,5–5,0, шаг 0,5) в фиксированную трёхуровневую **офлайн-метку релевантности** для персонального ранжирования. Это не новая разметка художественного качества фильма и не доказательство релевантности конкретному текстовому запросу.

| Метка | Правило | Положительный и отрицательный пример |
|---|---|---|
| **2** — высокая | `rating ≥ 4.0` | 4.0, 4.5, 5.0 → 2; 3.5 → не 2 |
| **1** — частичная | `3.0 ≤ rating < 4.0` | 3.0, 3.5 → 1; 2.5 → не 1 |
| **0** — низкая | `0.5 ≤ rating < 3.0` | 0.5, 1.0, 2.5 → 0; 3.0 → не 0 |
| **NA** — не оценено | нет оценки или ее невозможно подтвердить | нет строки / пустая оценка → **не 0** |
| **REVIEW** — спорно | недопустимый шаг, рейтинг за пределами шкалы или конфликт исходных дублей | 3.14, 6.0, 0.0 → в журнал и исключить до решения |

**Пограничные точки:** 2.5 → 0; **3.0 → 1**; 3.5 → 1; **4.0 → 2**. Порог принят **до** просмотра метрик test и применяется одинаково ко всем выборкам. Для HitRate@10 `positive = (label == 2)`. Для NDCG@10 метки 0/1/2 трактуются как градации наблюдаемой релевантности. **Отсутствие оценки не является оценкой 0.**

## Алгоритм

1. Установить источник по [реестру ЛР 4](../lab04-data-registry-cinematch/sources.md), проверить версию и допуск для учебного использования.
2. Прочитать поля по [схеме ЛР 4](../lab04-data-registry-cinematch/schema.md); проверить `userId`, `movieId`, `timestamp`, диапазон и шаг `rating`, наличие фильма в каталоге.
3. Для повторов `(userId, movieId)` заранее применить правило: оставить запись с максимальным timestamp, при равенстве — с большим номером строки; остальные логировать. В проверенном наборе таких повторов нет.
4. Назначить метку из таблицы, сохранить исходный рейтинг и версию `cinematch-labels-v1.0.0`; не редактировать вручную метки test ради улучшения качества.
5. Отложить случай `REVIEW` с описанием причины, не угадывать класс. Для изменения решения зафиксировать старое/новое значение и основание в журнале и поднять версию инструкции.
6. Для пилота выбирать только train-строки, хранить исходные и проверочные метки **раздельно**, не показывать проверяющей процедуре результат основной до завершения.

## Честная оценка и ограничение

Метка извлекается **из существующей пользовательской оценки**, а не создаётся независимым человеком. 4.5 у одного пользователя и 4.5 у другого не гарантируют равную степень удовольствия. Ранжирование проверяется по отложенным взаимодействиям; фильмы без оценки — `unjudged`, не отрицательные. Если позже добавится экспертная ручная разметка, нужны обученные разметчики, слепой пилот и отдельная оценка межэкспертного согласия.
