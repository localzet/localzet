## Алгоритм

1. Используем только `train.csv`, `validation.csv` из ЛР 6. **Test не используется** для выбора метода или подсчёта метрик.
2. Для каждого фильма считаем число оценок **`rating >= 4.0` исключительно в train**. Это глобальный рейтинг популярности, без жанровых признаков и без обучения персонализированной модели.
3. Сортируем по убыванию числа положительных оценок; при равенстве — `movieId` по возрастанию.
4. Для пользователя удаляем фильмы, уже встречавшиеся в **его train-истории**. Возвращаем первые `k = 10` из полного каталога фильмов, в том числе если у фильма ноль положительных оценок train (чтобы алгоритм был определён для любого допустимого `k`).
5. Метки validation из ЛР 6 используются **только для оценки:** `2` при `rating >= 4`, `1` при `3 <= rating < 4`, `0` при `rating < 3`. Неоценённые фильмы **не объявляются отрицательными**: только для офлайн-проксимерики имеют нулевой *gain* (невозможно признать попадание без явной оценки).
6. Нормализованный DCG использует `gain = 2^label - 1`. Recall@10 и HitRate@10 считают только отложенные оценки с label `2`. Для пользователей без положительного holdout эти две метрики не усредняются. NDCG не усредняется для пользователей с `IDCG = 0`.

Baseline детерминированный, `seed` для него не требуется. Сложная модель в будущем **может быть хуже** — это экспериментальная точка отсчёта, не гарантированная математическая нижняя граница.

## Запуск с нуля

Требуется Python **3.10+** и доступ к репозиторию целиком, поскольку подготовка данных переиспользует исходный код ЛР 6 (вместо дублирования реализации split).

```bash
git clone https://github.com/localzet/localzet.git
cd localzet/education/dgtu/ml-creative-industries/lab07-baseline-cinematch
python -m unittest discover -p 'test_baseline.py' -v
python baseline.py --prepared prepared --output results-local
```

По умолчанию модуль ЛР 6 сначала пробует **зеркало с проверкой Git SHA**, затем официальный архив GroupLens. Если сеть недоступна, вручную скачайте [`ml-latest-small.zip`](https://files.grouplens.org/datasets/movielens/ml-latest-small.zip) или CSV [из зафиксированного публичного зеркала](https://github.com/smanihwr/ml-latest-small), укажите локальный источник:

```bash
python baseline.py --source /path/to/ml-latest-small.zip --prepared prepared --output results-local
# или
python baseline.py --source /path/to/ml-latest-small --prepared prepared --output results-local
```

**Важно:** оригинальный ZIP может отличаться по контрольным хешам CSV от зафиксированного зеркала. Если проверка хеша не прошла, не отключайте её: получите версию CSV из указанного зеркала или зафиксируйте новую версию через полный аудит.

Файлы `prepared/` и `results-local/` генерируются локально и не коммитятся. Данные с псевдонимными `userId` не публикуются в виде исходных CSV.

## Ограничения и следующая гипотеза

Без персонализации алгоритм рекомендует всем один и тот же глобальный список (кроме просмотренного). Набор сильно разрежен, и отсутствие оценки в holdout **не доказывает** неинтересность фильма. Кроме того, дата добавления фильма в каталог отсутствует, поэтому возможна историческая недоступность части кандидатов. Измеряем не CTR, а ограниченные офлайн-метрики.

**Гипотеза для следующей работы:** персональный профиль жанров по train-истории, TF-IDF и косинусное сходство должны улучшать тот же validation по сравнению с глобальной популярностью. Split, словарь меток, `k` и определения метрик не менять без новой версии эксперимента.
