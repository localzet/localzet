# ЛР 4 · Схема данных CineMatch (v1)

**Единица анализа:** зависит от сущности. Для `movies.csv` — **один фильм**, для `ratings.csv` — **одна оценка фильма пользователем**, для `tags.csv` — **одно присвоение тега**. Нельзя считать фильмы, оценки, теги и варианты постеров независимыми равноправными наблюдениями.

## 1. Исходная схема (GroupLens MovieLens Latest Small)

| Таблица / поле | Тип и допустимость | Роль |
|---|---|---|
| `movies.movieId` | `int64`, положительный, уникальный в каталоге | PK, связь между файлами; не числовой ML-признак |
| `movies.title` | непустая строка UTF-8 (год может отсутствовать или быть неточным) | отображение, аудит |
| `movies.genres` | строка `Comedy\|Drama`, список жанров через `\|`, возможно `(no genres listed)` | **признак** content-based модели |
| `ratings.userId` | `int64`, псевдонимный идентификатор | пользовательский профиль, группировка; не независимый числовой признак |
| `ratings.movieId` | `int64`, ссылка на каталог | связь и фильтрация просмотренного |
| `ratings.rating` | `float`, от 0.5 до 5.0 с шагом 0.5 | целевая оценка, определение релевантности |
| `ratings.timestamp` | `int64`, Unix seconds (UTC) | **только** временной split/аудит; не признак ранжирования |
| `tags.userId`, `tags.movieId` | идентификаторы, как выше | связь, аудит |
| `tags.tag` | свободный текст UTF-8, непустой после trim | опциональные текстовые признаки только после проверки/очистки |
| `tags.timestamp` | `int64`, Unix seconds (UTC) | контроль доступности тега во времени |
| `links.movieId` | `int64` | связь |
| `links.imdbId`, `links.tmdbId` | строка/nullable целое | необязательные внешние ID; не основания для скачивания контента |

**Ключи и ссылки:** `movies.movieId` уникален; `ratings.movieId` и `tags.movieId` ссылаются на каталог. В наблюдениях оценок возможные повторные `(userId,movieId)` нужно обнаружить; перед split разрешать по заранее фиксированному правилу, например оставлять последнюю по `timestamp`, с журналом исключений. Сами CSV пока не проверены локально.

## 2. Производные поля `clean`

| Поле | Тип / правило | Назначение |
|---|---|---|
| `genres_list` | массив допустимых жанров; `(no genres listed)` — маркер отсутствия, не самостоятельный смысловой жанр | TF-IDF / признаки и сегментная проверка |
| `relevance` | `2`, если `rating >= 4.0`; `1`, если `3.0 <= rating < 4.0`; `0`, если `rating < 3.0` | черновик градуированной релевантности для оценки ранжирования |
| `positive` | boolean, `rating >= 4.0` | бинарная релевантность для HitRate@10 |
| `split` | `train`, `validation`, `test` | выборка оценки, назначенная согласно `split_and_plan.md` |
| `interaction_group` | хеш комбинации `(userId,timestamp)` | группировка оценок с одинаковым временем внутри пользователя |
| `source_id` / `source_version` | `ML-RAT` / `ml-latest-small-2018-09-26` | происхождение, версионирование |
| `rights_status` | `research_allowed`, `unknown`, `planned_synthetic` | допуск к использованию |
| `synthetic` | `false` для MovieLens, `true` для собственных демо-карточек | явная маркировка |
| `record_sha256` | SHA-256 нормализованной записи | обнаружение совпадений и аудит; не признак модели |

**Критичные границы:** не использовать `rating` или `relevance` из validation/test для построения профиля и baseline. Тег с `timestamp` позже проверяемого взаимодействия не должен становиться исторически доступным признаком, иначе появится утечка. Фильмы как каталог доступны для выдачи, но дата внесения в каталог неизвестна — реконструкция исторической доступности невозможна, это ограничение датасета.

## 3. Схема будущих событий приложения (ещё не собраны)

`event_id: UUID`, `session_id: UUID`, `pseudo_user_id: string`, `timestamp_utc: datetime`, `event_name: enum(recommendation_show,recommendation_click,watchlist_add)`, `request_id: UUID`, `movieId: int`, `position: int[1..10]`, `model_version: string`, `synthetic: bool=false`.

События не заменяют оценки MovieLens. Хранятся только после определения оснований, цели и сроков обработки. Сырую телеметрию и идентификаторы нельзя публиковать в открытом репозитории.

## 4. Конфиденциальность и аудит

Прямых ФИО и демографических полей в MovieLens нет. `userId` — псевдоним, не гарантия полной анонимности. Свободные теги потенциально могут содержать персональные сведения, поэтому публикация и показ отдельных текстов требуют проверки. `source_id`, `rights_status`, хеши и `split` — служебные поля **не для обучения модели**. Синтетические записи отделять физически от реальных.
